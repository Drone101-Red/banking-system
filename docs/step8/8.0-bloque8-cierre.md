# Bloque 8 — Cierre del Proyecto

## Resumen

El proyecto está completo. Sistema de banca en línea con backend en Go,
frontend en React, doble base de datos (PostgreSQL + TigerBeetle), y
chat con IA que ejecuta operaciones financieras en lenguaje natural.

`docker compose up` levanta los 4 servicios sin intervención manual.

## Lo que se entregó

### Backend (Go 1.24 + Chi)

- **15 endpoints REST**: auth (4), cuentas (2), transacciones (5),
  chat (2), utilidades (2).
- **Autenticación JWT** con HS256, bcrypt cost 12, anti-enumeración,
  timing attack mitigation.
- **Doble base de datos**: PostgreSQL (identidad) + TigerBeetle
  (financiero).
- **Idempotencia** en operaciones de escritura vía header
  `Idempotency-Key`.
- **Confirmación en dos fases** para operaciones del chat IA:
  el backend no confía en el modelo, genera un token de un solo uso.
- **Reconciliador** de usuarios PENDING cada 5 minutos.
- **Seed automático** de usuarios demo en `APP_ENV=development`.

### Frontend (React 19 + Vite 8 + Tailwind 3.4)

- **5 páginas**: Login, Register, Dashboard, Transactions, History.
- **Chat con IA** integrado en el Dashboard, con manejo de
  confirmación pendiente.
- **3 formularios** de transacciones (depositar, retirar, transferir)
  con búsqueda de destinatario por email/alias.
- **Historial paginado** con dirección calculada (in/out).
- **Idempotency-Key** generada con `crypto.randomUUID()`.
- **JWT interceptor** en axios + manejo de 401.
- **Servido con nginx** en Docker.

### Infraestructura

- **Docker Compose** con 4 servicios: postgres, tigerbeetle, backend,
  frontend.
- **Red custom** `banking_net` (172.30.0.0/24) con IP fija para TB.
- **Healthchecks** reales para todos los servicios.
- **`depends_on: condition: service_healthy`** para el orden de arranque.

## Decisiones técnicas clave

1. **Doble base de datos**: PostgreSQL para identidad, TigerBeetle para
   estado financiero. La fuente de verdad financiera es TigerBeetle.
2. **Estado PENDING/ACTIVE**: el usuario se crea primero en PG con
   status PENDING, luego se crea la cuenta en TB, luego se actualiza a
   ACTIVE. Si algo falla, el reconciliador recupera.
3. **Idempotencia**: header `Idempotency-Key` + SHA256(userID + key)
   para generar el ID de transferencia determinístico.
4. **Confirmación en dos fases**: token de un solo uso para
   operaciones de escritura. No es 2PC literal.
5. **Tool calling vs MCP**: se usa el formato OpenAI de function calling
   sobre OpenRouter. Los tools son funcionalmente equivalentes a MCP.
6. **Anti-enumeración**: mismo error para email inexistente y password
   incorrecta, con dummy bcrypt para timing constante.

## Problemas resueltos

| Problema | Solución |
|---|---|
| Endianness de `Uint128.Bytes()` | `binary.LittleEndian.Uint64(b[:8])` |
| `Nop()` no detecta caídas de TB | `LookupAccounts` con timeout externo |
| Cliente TB sin timeout configurable | Timeout externo con goroutine |
| Timezone: PG en UTC, Go en local | `time.Now().UTC()` |
| Docker Compose no hereda `.env` | Declarar variables explícitamente |
| `x/crypto v0.57.0` requiere Go 1.26 | Fijar a `v0.47.0` |
| Timeout de TB bajo carga | Subir a 5s + serializar en frontend |
| Dockerfile con nombre minúscula | Renombrar a `Dockerfile` |

## Cómo verificar la entrega

```bash
# 1. Clonar
git clone https://github.com/geanmunoz/banking-system
cd banking-system

# 2. Configurar
cp .env.example .env
# Editar .env con tu OPENROUTER_API_KEY
# Generar JWT_SECRET: openssl rand -hex 32

# 3. Levantar
docker compose up -d --build
sleep 40

# 4. Verificar
docker ps --filter name=banking-
curl -s http://localhost:8080/health | python3 -m json.tool

# 5. Abrir el navegador
# http://localhost
# Login: demo@banco.com / Demo1234!
```
