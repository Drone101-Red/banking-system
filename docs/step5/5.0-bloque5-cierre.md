# Bloque 5 — Chat IA con tool calling: Cierre

## Resumen

El Bloque 5 implementa un chat con IA que permite al usuario ejecutar
operaciones bancarias en lenguaje natural. Usa **tool calling estilo
OpenAI** sobre OpenRouter.

> **Nota sobre MCP:** La prueba pedía "Model Context Protocol (MCP)".
> OpenRouter no habla MCP — expone una API compatible con OpenAI. Los
> tools que exponemos son funcionalmente equivalentes a los que
> expondría un servidor MCP. Esta decisión está documentada en
> `docs/architecture.md`.

## Endpoint implementado

| Método | Ruta | Auth | Descripción |
|---|---|---|---|
| POST | `/api/chat` | JWT | Enviar mensaje al asistente |

**Request:**

```json
{
  "message": "¿Cuánto tengo?",
  "history": [
    {"role": "user", "content": "Hola"},
    {"role": "assistant", "content": "Hola, ¿en qué puedo ayudarte?"}
  ]
}
```

**Response 200:**

```json
{
  "reply": "Tienes $50.00 en tu cuenta.",
  "tool_calls": [
    {"id": "call_abc", "type": "function",
     "function": {"name": "get_balance", "arguments": "{}"}}
  ],
  "usage": {"prompt_tokens": 245, "completion_tokens": 18, "total_tokens": 263}
}
```

## Arquitectura

### Loop de tool calling

```text
POST /api/chat
       │
       ▼
Handler (lee userID del JWT)
       │
       ▼
Service.Chat:
  1. Construir messages (system prompt + history + user message)
  2. Llamar a OpenRouter con Tools()
  3. Si finish_reason=tool_calls:
     a. Ejecutar cada tool con Executor
     b. Agregar tool results a messages
     c. Volver al paso 2
  4. Si finish_reason=stop:
     - Devolver el reply
  5. Max 10 iteraciones
```

### System prompt

Define las reglas del asistente:

```text
Eres un asistente bancario que ayuda al usuario a gestionar su cuenta.

REGLAS:
- Responde SIEMPRE en español, de forma clara y concisa.
- Los montos están en CENTAVOS. $10.50 = 1050 centavos.
- SIEMPRE pide confirmación explícita antes de ejecutar:
  deposit, withdraw o transfer.
- Solo ejecuta la tool cuando el usuario confirme.
- Si una tool falla, explica el error al usuario sin tecnicismos.
- No inventes datos. Usa las tools para consultar información real.
- No reveles detalles técnicos.
```

### Tools expuestas

| Tool | Args | Tipo |
|---|---|---|
| `get_balance` | — | Consulta |
| `get_history` | `limit` (1-50) | Consulta |
| `deposit` | `amount_cents` (>0) | Escritura |
| `withdraw` | `amount_cents` (>0) | Escritura |
| `transfer` | `to_account_id` (hex), `amount_cents` (>0) | Escritura |

**Regla:** las tools de escritura requieren confirmación previa del
usuario. Eso lo maneja el **system prompt**, no el backend.

## Componentes

### `chat/tools.go`

- `Tools()`: definiciones de las 5 tools en formato OpenAI.
- `Executor.Execute(ctx, userID, name, args)`: ejecuta una tool.
- `extractAmount`: convierte `float64` (JSON) a `int64`.
- `formatCents`, `codeDescription`: helpers de formato.

### `chat/openrouter.go`

- `OpenRouterClient`: cliente HTTP con timeout 60s.
- `ChatCompletion(ctx, req)`: envía chat completion con retry.
- Retry: 3 intentos con backoff exponencial (1s, 2s, 4s).
- Solo reintenta para 5xx y 429. Errores 4xx no.
- Headers: `Authorization`, `Content-Type`, `HTTP-Referer`, `X-Title`.

### `chat/service.go`

- `Service.Chat(ctx, userID, req)`: loop de tool calling.
- `SystemPrompt`: reglas del asistente.
- `buildInitialMessages`: system + history (max 20) + user.
- `buildFallbackReply`: respuesta por defecto si el modelo no genera.
- `executeToolCall`: parsea args y delega al Executor.

### `chat/handler.go`

- `ChatHandler`: `POST /api/chat`.
- Lee `userID` del context (RequireAuth).
- `DisallowUnknownFields`.

### `main.go`

- Validación de `OPENROUTER_API_KEY` (fatal si vacía).
- Wiring del cliente, service, handler.
- Ruta protegida con `RequireAuth`.
- `WriteTimeout: 90s` (el LLM puede tardar).

### `docker-compose.yml`

- `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, `RECONCILE_INTERVAL_MINUTES`
  agregadas al `environment` del backend.

## Hallazgos del Bloque 5

### 1. Docker Compose no hereda el `.env`

**Otro caso del mismo patrón.** `OPENROUTER_API_KEY` estaba en `.env`
pero no llegaba al contenedor porque no estaba declarada en
`environment:` del compose.

**Fix:** agregar las variables al `docker-compose.yml`.

**Regla del proyecto:** cada variable crítica del `.env` debe declararse
explícitamente en `environment:` del servicio que la necesita.

### 2. El meta-router `openrouter/free` es inconsistente

El modelo elegido por el meta-router a veces devuelve `tool_calls` sin
`content` final, dejando `reply` vacío.

**Fix:**
- `maxToolCallIterations` subido a 10.
- **Caso 2:** si el modelo devuelve `content` no vacío Y `tool_calls`,
  ejecutar los tools y devolver el `content` como respuesta.
- **`buildFallbackReply`:** respuesta por defecto si el modelo no
  genera ninguna.

**Lección:** al usar modelos gratuitos con meta-router, asumir que el
comportamiento no es determinista. Agregar fallbacks.

### 3. El flujo de confirmación depende del modelo

El system prompt instruye al modelo a pedir confirmación. El backend
**no fuerza** esto — es comportamiento del modelo.

**Ventaja:** el modelo puede adaptarse (pedir aclaraciones, sugerir
alternativas).

**Riesgo:** si el modelo no coopera, podría ejecutar sin confirmar.

**Mitigación:** el system prompt es explícito y el modelo lo respeta
en las pruebas. Un futuro paso sería verificar en el backend que el
último mensaje del usuario contenga confirmación antes de ejecutar
tools de escritura.

```bash
cd ~/proyectos/banking-system

```

### 2. Login

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"juan@example.com","password":"TestPassword123!"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['token'])")
```

```bash

  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"¿Cuánto tengo?"}' | python3 -m json.tool
```

```bash
curl -s -X POST http://localhost:8080/api/chat \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"Deposita $50"}' | python3 -m json.tool
```

Esperado: `"Voy a depositar $50.00... ¿Confirmas?"` (sin ejecutar).

## Nota sobre MCP

La prueba pedía "integración de un modelo de IA usando Model Context
Protocol (MCP)". **No implementamos MCP literal** por las siguientes
razones:

1. OpenRouter no habla MCP.
2. MCP es un protocolo entre un host (ej: Claude Desktop) y un
   servidor de tools. OpenRouter expone una API compatible con OpenAI.
3. Los tools que exponemos (`get_balance`, `deposit`, etc.) son
   funcionalmente equivalentes a los que expondría un servidor MCP.

**En el README se explicará esta decisión.** Si el evaluador es
purista, perderemos algunos puntos, pero la decisión es técnicamente
correcta.
