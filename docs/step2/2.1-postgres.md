# Paso 2.1 — PostgreSQL con schema inicial

## Objetivo
Levantar PostgreSQL en Docker y verificar que las tablas `users` y
`transactions_log` se crean correctamente la primera vez que arranca.

## Archivos involucrados
- `docker-compose.yml` (solo el servicio `postgres` por ahora)
- `db/init.sql` (schema completo)

## Cómo levantar

```bash
docker compose up -d postgres
```

La primera vez descarga la imagen `postgres:16-alpine` (~80 MB).

## Cómo verificar

### 1. El contenedor está corriendo y healthy

```bash
docker ps --filter name=banking-postgres
# Esperado: STATUS "Up X seconds (healthy)"
```

Si dice `(health: starting)`, espera 5-10 segundos y repite.

### 2. Las tablas existen

```bash
docker exec banking-postgres psql -U banking_user -d banking -c "\dt"
```

Esperado:

```
              List of relations
 Schema |       Name        | Type  |    Owner
--------+-------------------+-------+--------------
 public | transactions_log  | table | banking_user
 public | users             | table | banking_user
(2 rows)
```

### 3. La columna `tb_account_id` es BYTEA

```bash
docker exec banking-postgres psql -U banking_user -d banking -c "\d users"
```

Esperado (fragmento relevante):

```
   Column       |            Type             | Nullable
----------------+-----------------------------+----------
 id             | uuid                        | not null
 email          | character varying(255)      | not null
 password_hash  | character varying(255)      | not null
 full_name      | character varying(255)      | not null
 tb_account_id  | bytea                       | not null   ← clave
 created_at     | timestamp without time zone |
 updated_at     | timestamp without time zone |
```

### 4. Los índices existen

```bash
docker exec banking-postgres psql -U banking_user -d banking -c "\di"
```

Esperado: 5 índices (`idx_users_email`, `idx_users_tb_account_id`,
`idx_txlog_debit`, `idx_txlog_credit`, `idx_txlog_created`).

## Troubleshooting

### El contenedor reinicia en loop

```bash
docker logs banking-postgres --tail 50
```

Causas comunes:
- Puerto 5432 ya ocupado en el host → cambiar `ports` a `"5433:5432"`.
- Volumen corrupto de una corrida previa → `docker compose down -v` y reintentar.

### Las tablas no existen pero el contenedor está healthy

`init.sql` solo se ejecuta **la primera vez** que arranca con un volumen
vacío. Si el volumen ya existía de antes, se ignora. Para forzar:

```bash
docker compose down -v    # -v borra volúmenes
docker compose up -d postgres
```

## Cómo limpiar

```bash
# Bajar el contenedor, mantener datos
docker compose down

# Bajar y borrar datos (volver a estado cero)
docker compose down -v
```
