# Paso 2.3 — Backend minimo con /health

## Objetivo
Levantar el backend Go en Docker, conectado a PostgreSQL, exponiendo
GET /health que devuelve el estado de la base de datos.

**Sin TigerBeetle todavia.** Eso es el paso 2.4.

## Archivos involucrados
- `backend/Dockerfile` (nuevo)
- `backend/cmd/server/main.go` (nuevo)
- `backend/internal/db/postgres.go` (nuevo, solo conexion + Ping)
- `backend/internal/apperr/apperr.go` (nuevo, tipo de error unificado)
- `docker-compose.yml` (agrega servicio backend)

## Dependencias Go necesarias
```bash
cd backend
go get github.com/go-chi/chi/v5@latest
go get github.com/lib/pq@latest
go mod tidy
Dockerfile multi-stage
Builder (golang:1.24-bookworm): compila el binario.

build-essential: preparado para cgo (TB lo necesita en 2.4).

CGO_ENABLED=1: explicito, no dependemos del default.

Runtime (debian:bookworm-slim): ejecuta el binario.

ca-certificates: para HTTPS a OpenRouter en Bloque 5.

No alpine: cgo necesita glibc.

Como levantar
bash
cd ~/proyectos/banking-system
docker compose up -d --build
Primera vez tarda ~1-2 min (descarga golang:1.24, compila).

Como verificar
1. Los 3 contenedores corriendo
bash
docker ps --filter name=banking-
# Esperado: postgres (healthy), tigerbeetle (healthy), backend (Up)
El backend no tiene healthcheck todavia, asi que aparece como Up sin estado.

2. /health responde healthy
bash
curl -s http://localhost:8080/health | python3 -m json.tool
Esperado:

json
{
    "postgres": "ok",
    "status": "healthy"
}
HTTP status 200.

3. Logs del backend limpios
bash
docker logs banking-backend --tail 20
Esperado:

text
✅ PostgreSQL conectado
🚀 Servidor en :8080
4. Test de resiliencia: parar Postgres
bash
docker compose stop postgres
sleep 3
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/health
# Esperado: 503

curl -s http://localhost:8080/health | python3 -m json.tool
# Esperado: {"postgres":"error","status":"degraded"}

# Restaurar
docker compose start postgres
sleep 5
curl -s http://localhost:8080/health | python3 -m json.tool
# Esperado: healthy de nuevo
Troubleshooting
El backend reinicia en loop con "connection refused"
El depends_on: condition: service_healthy deberia evitarlo. Si pasa:

Verificar que postgres pasa a healthy: docker ps --filter name=banking-postgres

Ver logs: docker logs banking-backend --tail 50

El build falla con "go.sum mismatch"
bash
cd backend
go mod tidy
cd ..
docker compose build --no-cache backend
El backend arranca pero /health devuelve 500
Ver logs: docker logs banking-backend --tail 50.
Probable: el DSN esta mal formado o Postgres no acepta conexiones.

Como limpiar
bash
# Bajar todo, mantener datos
docker compose down

# Bajar todo, borrar datos
docker compose down -v
