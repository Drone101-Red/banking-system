# Paso 3.6 — Implementación de Login

## Objetivo

Implementar `POST /api/auth/login` que autentica al usuario y devuelve
un JWT firmado con HS256.

Al terminar 3.6, un cliente puede:

1. Enviar `{email, password}` a `POST /api/auth/login`.
2. Recibir `200 OK` con `{token, user}` si las credenciales son válidas
   y el usuario está ACTIVE.
3. Recibir `401 Unauthorized` con `INVALID_CREDENTIALS` si el email no
   existe o la password es incorrecta (sin distinguir entre ambos).
4. Recibir `401 Unauthorized` con `ACCOUNT_PENDING` si la password es
   correcta pero el usuario está en PENDING.

## Componentes

### 1. `jwt.go`

Genera y valida JWT con HS256.

- `GenerateToken(user, secret, expiry) (string, error)`
- `ParseToken(tokenString, secret) (*Claims, error)`

**Claims:**

```go
type Claims struct {
    UserID      string `json:"sub"`
    TBAccountID string `json:"tb_account_id"`
    jwt.RegisteredClaims
}
```

**Seguridad:**

- `jwt.WithValidMethods([]string{"HS256"})` — previene el ataque "alg: none".
- `jwt.WithIssuer(Issuer)` — rechaza tokens de otros emisores.
- `Issuer = "banking-system"`.

**Tests unitarios:** 10. Incluyen el test crítico `TestParseToken_AlgNone` que
verifica que un token firmado con `alg: none` es rechazado.

### 2. `service.Login`

Flujo:

```text
Login(ctx, req):
  1. Normalizar email.
  2. Validar email + password no vacíos.
  3. Buscar usuario por email:
     - No existe → dummy bcrypt + 401 INVALID_CREDENTIALS
  4. Comparar password:
     - No coincide → 401 INVALID_CREDENTIALS
  5. Verificar status:
     - PENDING → 401 ACCOUNT_PENDING
     - ACTIVE → continuar
  6. Generar JWT.
  7. Devolver (user, token, nil).
```

**Contrato de errores:**

| Situación | HTTP | Código |
|---|---|---|
| Email vacío | 400 | `EMAIL_REQUIRED` |
| Password vacía | 400 | `PASSWORD_REQUIRED` |
| Email inexistente | 401 | `INVALID_CREDENTIALS` |
| Password incorrecta | 401 | `INVALID_CREDENTIALS` |
| Password correcta + PENDING | 401 | `ACCOUNT_PENDING` |
| Password correcta + ACTIVE | 200 | (user + JWT) |

### 3. Timing attack mitigation

Cuando el email no existe, **igual hasheamos** contra un dummy bcrypt
pre-generado (`dummyPasswordHash`), para que el tiempo de respuesta sea
constante independientemente de si el email existe o no.

**Razón:** sin esta mitigación, un atacante podría medir el tiempo de
respuesta y determinar si un email está registrado:
- Email inexistente → return inmediato (<1ms).
- Email existente → bcrypt compare (~300ms).

**Implementación:**

```go
const dummyPasswordHash = "$2a$12$pHpHZ1qj/K0ErwbTaxyDrO2e8KYQRhlJWOWY7EXoKYUq443Wnqfsm"

// En Login, si el email no existe:
_ = password.Compare(dummyPasswordHash, req.Password)
return nil, "", apperr.Unauthorized("INVALID_CREDENTIALS", "Credenciales inválidas")
```

**No se genera el hash en runtime** (costaría 300ms en cada login con
email inexistente). Está pre-generado como constante.

## Hallazgo: JWT_SECRET con caracteres especiales rompe Compose

Al agregar `JWT_SECRET` al compose, apareció el error:

```text
invalid interpolation format for services.backend.environment.JWT_SECRET.
You may need to escape any $ with another $.
${7t3ZZZ0nIVIS3Cb5zQP3S8x+ui0JjYUZ1nhCcimh3AM=}
```

**Causa:** el secreto base64 contenía `+`, `/`, `=`, que Docker Compose
interpretaba como sintaxis de interpolación.

**Solución:** regenerar el secreto en formato **hex**:

```bash
openssl rand -hex 32
# Salida: 64 caracteres hex, sin caracteres especiales
```

**Regla del proyecto:** los secretos para Docker Compose deben usar hex
o base64url sin padding. Evitar base64 estándar con `+`, `/`, `=`.

### 3. Anti-enumeración

```bash
T2=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"juan@example.com","password":"WrongPassword!"}')

T3=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"noexiste@example.com","password":"AnyPassword123!"}')

[ "$T2" = "$T3" ] && echo "✅ Sin enumeración" || echo "❌ Hay enumeración"
```

Esperado: `✅ Sin enumeración`.
